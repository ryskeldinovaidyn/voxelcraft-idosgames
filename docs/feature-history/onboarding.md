# Onboarding Tutorial Director V1

The first-session problem was concrete: a new survival player spawned with an empty inventory, but the only sword recipe required a 3×3 workbench and the game never displayed its ingredients. V1 keeps the existing inventory, crafting grid, recipe registry, event bus, HUD, day/night cycle, mob spawner, and save store. It adds a second, shapeless wooden-sword recipe for the existing 2×2 inventory grid: two planks plus one stick. One oak log yields four planks; two make four sticks, leaving two for the sword. The original 3×3 sword recipe still works.

`OnboardingDirector` observes pickups, crafting, inventory opening, hotbar selection, hits and kills, placement, sleep, movement, and time of day. The `TutorialHintManager` handles presentation, priority, deduplication, cooldowns, and suppression while a UI is open or the player is in combat. No tutorial step blocks input. A small recipe card appears only for a player who has not learned the first weapon: it shows live counts for planks and sticks, the next source action, and which grid to use. The first crafted sword goes to a free hotbar slot; if none exists, standard cursor/inventory behavior remains. The normal craft sound and a brief toast provide feedback.

A persistent in-game `TutorialGuide` now appears after five seconds of active play and shows one concrete action at a time. It follows actual progress through movement, wood, inventory, planks, sticks, sword crafting, equipment, combat and shelter. It stays visible until the action is done, hides over inventory and other UI, and yields during combat except for the combat instruction. The inventory recipe card provides the detail while the inventory is open. The pause menu has **Начать обучение заново** for a returning player who wants to see the flow again, plus a show/hide control; neither changes ordinary game progression.

After 14 seconds of active survival play, movement or resource hints can appear if still relevant. Once the player opens inventory without sufficient materials, extra material help appears after 40, 85, and 145 seconds without completion. For uncollected wood, a one-time targeted search at level 2 outlines the nearest loaded log, and level 3 names its approximate distance. The search is throttled and the marker disappears on pickup. `StarterResourceZone` checks a 40-block radius when a world is first generated. If no logs are present, it adds a short fallen log on open land within 22 blocks; on an extreme spawn with no suitable land, the game drops one log by the player. Existing saved worlds are never modified by this rule.

On the first survival encounter, the ordinary overworld hostile spawner selects a single zombie at a time until the player defeats a hostile mob. It does not script a spawn or modify multiplayer spawning. Near sunset, a short shelter hint appears. A placed bed, sleep, or four building blocks plus a light source counts as understanding shelter. The latter is deliberately an approximate milestone, not a house detector.

Reusable player knowledge is stored in browser localStorage; per-world milestones, elapsed and stalled time, and telemetry timestamps are stored in optional `SaveData.onboarding`. This does not use the separate lobby Profile module because VoxelCraft has no profile data API and modules cannot import one another. Therefore knowledge is per browser origin, not synchronized between devices or isolated by login account. Old saves without onboarding data infer basic competence from a weapon in inventory; worlds with a large inventory, several achievements, or substantial experience skip the beginner flow entirely. World Pulse remains entirely separate, with no tutorial mentions of its events.

`/tutorial status` reports mode, knowledge, world milestones, current hint and queue, assist level, current objective, time without materials, and milestone times. `/tutorial reset` resets knowledge on this browser and progress in the current world. `/tutorial auto|full|light|off` changes help; `/tutorial set <mode>` is an alias. `/tutorial trigger movement|crafting|weapon|combat|shelter` previews a hint. The setting and knowledge survive reload. Milestones emit local `onboardingMilestone` events, but the project has no analytics upload pipeline.

Automated tests cover the one-log 2×2 recipe, event-driven progress, first-sword hotbar placement, three delayed hint levels and cancellation, save/reload and legacy inference, and starter wood placement. The test harness does not measure real first-user completion time, rendering on phones, or actual natural tree visibility; those need a playtest.
